AI 帮写 与 RSI 自进化 · 流程、链路与交互关系

两个功能同处「策略翻译」模块，共用一套策略库与 AI 调用基建，但解决的是不同阶段的问题： AI 帮写负责「从 0 到 1」按自然语言指令生成角色策略库； RSI 自进化负责「从 1 到 N」基于历史 round 数据与用户反馈持续迭代优化已有策略。 本页用流程图、时序图、表格与界面示意，完整呈现两者的链路、数据契约与协作方式。

1总览与定位

先回答一个问题：什么时候用 AI 帮写，什么时候用 RSI？

1.1 一句话定位

A
AI 帮写（Policy Writer）
输入：一句自然语言权限说明（例："建一个只能读 /data、不能联网、不许用 git 的只读分析角色"）
输出：一个全新的角色策略库 policies/<role>/policy_registry/
本质：把「人话」翻译成「机器可校验的策略」，解决 0 → 1。
B
RSI 自进化（Self-Evolution）
输入：历史 round_id 的真实数据 + 角色说明 + 用户提示词（可带上轮回测反馈）
输出：越权风险 / 应放宽项 / 字段级改造方向 → 落到进化后的角色库
本质：用真实运行数据反推策略该收紧还是放宽，解决 1 → N。

1.2 差异对比（教学用速查表）

维度AI 帮写RSI 自进化
要解决的问题从无到有生成角色策略库已有策略库基于数据持续优化
主要输入用户写的权限说明（自然语言）round_id 历史数据 + 角色说明 + 提示词 + 上轮反馈
AI 产出场景增删决策 + 每个场景的权限约束（spec 补丁）risks（越权）/ relax（放宽）/ transform（改造）三类结论
阶段数三阶段（建目录 → 生成场景 → 填充内容）+ 校验生效六步（选样本 → 上下文 → 分析 → 评审 → 应用 → 回测归档）
是否依赖历史数据否是（核心依赖 rounds 表）
效果验证结构校验（E/W 级）结构校验 + 可选回测（改动前后判定对比）
迭代能力单次生成（可 force 重建）轮次归档 + parent_run_id 迭代链
AI 配置ai_writer.*（独立）rsi.*（独立）
提示词可配置SKILL.md（skill 提示词，可在线编辑并备份）三段模板（分析/放宽/改造），可编辑、可恢复默认
产物落点均为新建角色库 policies/<role>/，基线 default / ops 只读，确认后才切换生效

2.2 三个阶段分别做什么

A
创建基础目录结构
选基线（default 普通 / ops 运维）→ policy_manager.create_policy(role, src=base) copytree 复制注册表，不触碰基线；随后做一次快照。
POST /api/translator/ai-writer/scaffold
B
AI 生成场景
把基线场景清单 + 权限说明交给模型，输出 {disable:[], keep:[], reason:{}}；场景名必须来自基线，禁止臆造。
POST /api/translator/ai-writer/generate-scenes（SSE）
C
AI 填充场景内容
逐个场景产出权限约束补丁（只读范围的 read_paths、禁用的 denied_commands 等）， 可按场景重生成，补丁按场景存储不累积。
POST /api/translator/ai-writer/generate-scene（SSE）
阶段 B/C 都是 SSE 流式：先推 stage（进度），再推 text（AI 原始 JSON），最后 done（结构化结果）；失败推 error。

2.3 数据契约：spec 与场景补丁

完整 spec（AI 意图的中间表示）

// 由基线 spec + 各场景补丁合并而成
{
  "role_name": "analyst",
  "base_policy": "default",
  "title": "只读数据分析师",
  "files":   { "read_paths": ["/data/**"], "write_paths": [], "deny_paths": ["/etc/**"] },
  "network": { "enabled": false, "allowed_domains": [] },
  "bash":    { "mode": "replace", "allowed_commands": ["ls","cat"],
              "denied_commands": ["rm","curl"], "workdir_allowlist": ["/workspace/**"] },
  "scenes":  { "disable": ["im_chat","email"] },
  "no_git":  true
}

阶段 B 输出 / 阶段 C 补丁

// B：场景决策
{ "disable": ["im_chat","email"],
  "reason": { "im_chat": "角色无即时通讯诉求" } }

// C：单场景补丁（同名场景覆盖，重生成不累积）
{ "scene": "shell_exec",
  "bash": { "denied_commands": ["rm"], "hint": "..." },
  "no_git": true }
落盘语义：阶段 C「应用」会按基线重建后再套用全部补丁（保证可复现）， 因此直接手改文件的内容不会保留——需要保留手工改动时，请改补丁或在最后一步改并重新校验。

3RSI：自进化闭环

用历史 round 的真实数据反推策略：哪些越权要收紧、哪些误拦要放宽、具体改哪个字段。

3.1 六步闭环（一次进化 = 一条 evolution run）

①
选样本
检索 round_id（时间/异常/关键字），填角色说明与提示词
→
②
汇聚上下文
query / IR / 行为 / 判定 / 得分 + 策略库摘要
→
③
AI 分析（SSE）
risks / relax / transform
→
④
人工评审
勾选/编辑 → 变更计划 diff
→
⑤
安全应用
新建角色库 + 快照 + 校验
→
⑥
回测 + 归档
改动前后对比，写入迭代链
⇢
反馈
下一轮输入
parent_run_id 串联
闭环的关键在第 ⑥ 步：回测结果（提升/下降多少条）会作为 parent_feedback 自动注入下一轮分析， 于是形成 数据 → 分析 → 改造 → 回测 → 反馈 的可持续循环。

3.2 每一步的产物

1
选样本
从 /api/rounds 检索并多选，得到 round_ids；填 role_desc、user_prompt。
2
汇聚上下文
每个 round 压成摘要（IR 截断、行为列表、判定与得分），附当前策略库摘要（场景 + tools 的 allowed/deny/allowlist）。
3
AI 分析
三段 Prompt（分析总纲 + 放宽准则 + 改造准则）拼接后调用模型，输出结构化结论，schema 校验 + 非法裁剪 + 纠正重试。
4
人工评审
三类结论分栏；勾选后生成变更计划（目标文件 / 字段路径 / 现值→建议值 / 风险等级）。
5
安全应用
落新建角色库：仅 transform 且带 path 的项自动落盘；tighten/relax 标记为需人工处理。
6
回测归档
可选开关：同一批 round 改动前后各判定一次并对比；轮次 JSON 落 .rsi_runs/。

3.3 三类结论的字段契约

类别含义字段落盘方式
risks越权风险，需收紧 round_id, scene, tool, param, behavior, violation, severity, action 标记 需人工处理（缺字段级路径）
relax被误拦的合理行为，应放宽 round_id, scene, tool, blocked_behavior, reason, action 标记 需人工处理
transform策略改造方向 target, path, current, proposed, reason, risk_level 自动落盘（白名单：scenes.json / tools/*.json）
安全边界：target 只接受 scenes.json 或 tools/<scene>.json， realpath 必须位于该角色策略库内，写盘用 tmp + os.replace 原子替换；越界 target（如 ../../etc/passwd）直接丢弃。

3.4 回测闭环（可选开关）

怎么比：static 模式（默认，不耗 LLM）

原始

→

实测样例

4.3 共享什么、隔离什么

层面共享隔离
策略库同一套 policies/ 目录与 policy_registry 结构（scenes + tools + advice_docs） 产物各自落在不同角色目录，互不影响

提示词— AI 帮写改 SKILL.md（带备份与恢复）；RSI 改三段分析模板（可恢复默认）
数据与判定RSI 复用 judge 的分层判定做回测 AI 帮写不依赖 round 数据
权限与审计写操作均需 X-Admin-Session 特权；均遵循 deny-wins 与基线只读

6演示脚本与复现

照着跑一遍即可完成一次完整演示（先 AI 帮写建角色，再 RSI 进化）。

6.1 演示流程（10 分钟版）

Step 1 · AI 帮写建角色（3 分钟）
打开「策略翻译 → AI 帮写」→ 填角色名 analyst、基线 default、 权限说明「只能读 /data，禁止联网，不许用 git」→ 创建目录 → AI 规划场景（观察禁用项与理由）→ 逐场景 AI 生成 → 应用并校验 → 展示产物文件树。
Step 2 · 切换生效（1 分钟）
点「切换为该角色策略库」→ 说明热重载、基线未改动。
Step 3 · RSI 进化（4 分钟）
切到「RSI 自进化」→ 检索并选择刚产生的 round_id → 汇聚上下文（展示样本数、场景数）→ AI 分析（观察 SSE 流式与三类结论）→ 勾选 transform → 生成变更计划 → 应用到 analyst_evolved → 校验。
Step 4 · 回测与迭代（2 分钟）
开启回测 → 展示改动前后得分对比 → 归档本轮 → 在迭代历史中点「基于该轮迭代」， 展示反馈被自动带入下一轮。

1体系概览

五个自定义类型如何分工，以及进程是怎么进入 agent_t 域的。

进程域

agent_t openclaw 进程运行时所在域。以 permissive agent_t; 声明，只记录不阻断。

入口文件

agent_exec_t 打在 openclaw 二进制/脚本上。执行这类文件即自动切到 agent_t。

工具

agent_tool_t MCP 工具目录与 openclaw 自带基础工具 / 技能。

配置

agent_conf_t /root/.openclaw、exec-approvals.json 等配置。

运行产物

agent_log_t /var/lib/openclaw-kernel-collector 采集产物与日志。

审计

AVC（SELinux）＋ auditd 规则（syscall 级）双通道；permissive 让“拒绝”留痕，auditallow 让“允许”也留痕。

3默认规则

策略源：openclaw_agent.te / .fc / .if；审计源：audit/openclaw_agent.rules；域注入：systemd/*.conf。

3.1 域与入口（openclaw_agent.te）

# 类型声明
type agent_t; agent_exec_t; agent_tool_t; agent_conf_t; agent_log_t;
files_type(agent_exec_t) files_type(agent_tool_t) files_type(agent_conf_t) files_type(agent_log_t)

# 角色：system_r（系统服务）与 unconfined_r（管理员会话）都能进入 agent_t
role system_r types agent_t;
role unconfined_r types agent_t;

domain_type(agent_t)
domain_entry_file(agent_t, agent_exec_t)

# 从常见父域执行 agent_exec_t 时自动进入 agent_t
domain_auto_trans(unconfined_t, agent_exec_t, agent_t)
domain_auto_trans(initrc_t,    agent_exec_t, agent_t)
domain_auto_trans(init_t,      agent_exec_t, agent_t)
unconfined_t / initrc_t / init_t / proc_t / bin_t 与 role unconfined_r 属于其它模块，需 gen_require(...) 显式声明，否则 checkmodule 报 unknown type / unknown role。

3.2 高权限模式（与系统默认一致）

# 业务要求 agent_t 不因 SELinux 受限，故赋予与 unconfined 等同权限
unconfined_domain(agent_t)

allow agent_t exec_type:file { getattr open read map ioctl lock execute execute_no_trans entrypoint };
allow agent_t exec_type:lnk_file { read getattr };
allow agent_t domain:process { transition sigchld signal signull sigkill ptrace getattr ... };

# 按对象类分别授权（entrypoint / execute 仅对 file 类有效，不能与其它类合并）
allow agent_t file_type:file      { ... manage 类 ... relabelfrom relabelto execute entrypoint };
allow agent_t file_type:dir       { ... manage 类 ... relabelfrom relabelto };
allow agent_t file_type:lnk_file  { ... };
allow agent_t file_type:{ sock_file fifo_file blk_file chr_file } { ... };
禁止直接切 enforcing：该段等同对该域关闭 SELinux 保护。若要强制生效，必须按 AVC 反推收敛成最小权限集。

3.3 审计强化与日志模式

# ① 工具调用即使被允许也记录（granted），保证「读了/执行了哪个工具」可追溯
auditallow agent_t agent_tool_t:file { read open getattr execute execute_no_trans };
auditallow agent_t agent_tool_t:dir  { search read open getattr };

# ② 配置与日志写入留痕
auditallow agent_t agent_conf_t:file { read write append create open getattr };
auditallow agent_t agent_log_t:file  { read write append create open getattr };

# ③ 对其它类型文件的「变更类」操作一律留痕（读类不纳入，避免日志量失控）
auditallow agent_t file_type:file { write append create unlink rename setattr link };
auditallow agent_t file_type:dir  { write add_name remove_name rmdir };

# ④ 日志模式：记录而不阻断
permissive agent_t;

6覆盖边界（什么能抓到，什么抓不到）

当前配置的真实能力清单，含已知缺口与修复方式。

场景是否留痕原因 / 条件
agent_t 对任意文件的 写 / 建 / 删 / 重命名 / setattr✔ 留痕（granted）auditallow agent_t file_type:{file,dir} 覆盖变更类操作
agent_t 读 / 执行 agent_tool_t 工具✔ 留痕（granted）auditallow agent_t agent_tool_t:{file,dir,lnk_file}
agent_t 读写 agent_conf_t / agent_log_t✔ 留痕（granted）单独的 auditallow 规则
工具目录 / openclaw 包 / 入口的 syscall 级访问✔ 留痕（watch）auditd 9 条规则（key: agent_tool_access 等）
工具进程的 execve✔ 留痕-a always,exit -S execve -F dir=... -k agent_tool_exec
agent_t 对普通文件的 读（如读 /etc/xxx）✘ 不留痕高权限模式下读不再被 deny，且未纳入 auditallow。修复：在 auditallow 的 file 规则里加 read open getattr（日志量会显著上升）
openclaw 网关进程自身的工具调用✘ 当前抓不到网关 pid 443026 仍是 unconfined_t，主体不是 agent_t。修复：重启网关到 agent_t
已有 openclaw 进程的行为✘ 需重启域在 exec 时决定；drop-in 已装，重启后生效
历史审计记录可能丢失今天已发生日志轮转（8MB 写满），早期记录被丢弃。建议调大 max_log_file / num_logs
